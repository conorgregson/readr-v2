# Readr v2.2 — API Integration Blueprint

Persistence Migration Phase

---

# Purpose

v2.2 replaces local-first persistence with API-backed storage
without rewriting the React UI.

This phase isolates persistence risk.

No new UX features are introduced.

---

# Migration Strategy

## Current (v2.1)

UI → Store → Service → localStorage

## Target (v2.2)

UI → Store → Service → API Client → Express → Prisma → PostgreSQL

UI must remain unchanged.

---

# Migration Phases

---

## Phase 1 — API Client Layer

- Create typed client services in `client/services/api/`
- Replace local service calls with fetch wrappers
- Maintain identical method signatures

Example:

```ts
BooksService.create(); // unchanged signature
```

Internal implementation changes only.

---

## Phase 2 — Dual-Write Validation (Optional)

Temporarily:

- Write to API
- Validate response
- Compare with local expectations

Used only during development.

---

## Phase — Remove Local Storage

- Remove local persistence code
- Delete migration helpers
- Keep normalization guards

---

# API Requirements

## Books

- GET /books
- POST /books
- PATCH /books/:id
- DELETE /books/:id

## Sessions

- GET /sessions
- POST /sessions
- PATCH /sessions/:id
- DELETE /sessions/:id

Must preserve:

- Deterministic sorting
- Undo capability
- Timestamp invariants

---

## Critical Invariants

- No component talks directly to fetch
- Stores remain write gatekeepers
- Service layer abstracts IO
- No behavioral change allowed

---

## Risk Areas

- Async timing affecting undo
- Selection state during mutation
- Sort order differences from server
- Timestamp authority (server vs client)

---

## Exit Criteria

- LocalStorage fully removed
- All CRUD flows API-backed
- No Tier 0 regression
- CI passing
- Manual parity audit complete

---

## Non-goals

- No bulk edit
- No badges
- No analytics
- No schema redesign
