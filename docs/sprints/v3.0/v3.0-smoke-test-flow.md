# Smoke-Test Flow — Readr v3.0

This smoke-test flow is intended to be fast, repeatable, and good enough to catch obvious deployment problems immediately after release.

---

## Purpose

Use this flow after deployment to confirm that:

- the frontend loads
- the backend is healthy
- auth works
- core authenticated communication still works
- no obvious production regressions are present

---

## Minimum Smoke-Test Flow

### 1. Check Backend Health

- open the deployed backend health endpoint
- confirm it returns success
- confirm response looks healthy

**Expected result:** `/health` responds successfully

---

### 2. Load the Frontend

- open the deployed frontend URL
- confirm the app loads normally
- confirm there is no blank screen or fatal error state

**Expected result:** frontend renders successfully

---

### 3. Check Console / Network Early

- open browser devtools
- inspect Console
- inspect Network during initial load

**Expected result:**

- no obvious fatal console errors
- no obvious broken asset loads
- no obvious failed startup API requests

---

### 4. Test Login

- sign in with a valid account
- confirm login completes successfully
- confirm app enters authenticated state

**Expected result:** login works and protected state becomes available

---

### 5. Test a Protected Flow

- load a protected route or authenticated area
- confirm frontend can successfully reach the deployed backend
- confirm expected protected requests return success

**Expected result:** authenticated API communication works

---

### 6. Test Logout

- log out
- confirm session/auth state clears correctly
- confirm protected areas behave as expected after logout

**Expected result:** logout works and auth state resets correctly

---

## Recommended Quick Checks

These are optional but helpful if the release touched related areas.

### API / Auth

- verify no unexpected 401s after login
- verify no route mismatches or unexpected 404s
- verify no obvious CORS issues

### Frontend

- verify no runtime crash after navigation
- verify environment-driven values look correct
- verify deployed build is using the intended backend target

### Backend

- verify startup logs look clean
- verify app remains healthy a few minutes after deploy

---

## Pass Criteria

The smoke test passes if:

- frontend loads
- `/health` is healthy
- login works
- logout works
- authenticated requests succeed
- no obvious console/network failures appear during core flow

---

## Failure Handling

If any smoke check fails:

1. identify whether the problem is frontend, backend, auth, env, or routing
2. capture the failing page/request/log
3. decide whether the issue is minor or release-blocking
4. rollback or redeploy last known good version if needed
5. re-run the smoke-test flow after any fix
