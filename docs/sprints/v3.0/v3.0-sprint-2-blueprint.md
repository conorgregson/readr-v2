# Sprint 2 Blueprint — Docker & Local Environment Standardization

Readr v3.0

**Objective:** Standardize local development with Docker so the app is easier to run, test, and maintain across environments.

---

## Sprint 2 Goal

- Local backend runs in a containerized workflow
- Supporting local services are easier to orchestrate
- Local environment setup becomes more predictable
- Docker improves consistency without replacing the current hosted stack

---

## Scope

### Containerization

- Add Dockerfile for backend
- Add optional Dockerfile for frontend if useful
- Add `.dockerignore` files
- Validate production-style backend container startup

---

### Local Orchestration

- Add `docker-compose.yml` for local development
- Support local API + database workflows through Compose
- Ensure environment variables work correctly inside containerized setup
- Document how Docker integrates with existing dev flow

---

### Developer Experience

- Minimize setup friction for local development
- Ensure clean startup/shutdown workflow
- Validate that Docker-based local flow does not break existing scripts
- Keep non-Docker local workflow optional if desired

---

## Acceptance Criteria

- Backend container builds successfully
- Docker Compose starts the required local services
- Local development can run from a documented container workflow
- Environment configuration works inside Dockerized setup
- Existing development workflow is either preserved or clearly replaced

---

## Deliverables

- backend `Dockerfile`
- optional frontend `Dockerfile`
- `.dockerignore` files
- `docker-compose.yml`
- README local Docker setup section

---

## Notes

- Docker is included because it solves a real consistency problem.
- This sprint should improve setup clarity, not add unnecessary complexity.
- Kubernetes remains out of scope.
