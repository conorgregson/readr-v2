# Release Checklist — Readr v3.0

Use this checklist before, during, and after deployment to reduce release risk and keep the process repeatable.

---

## Pre-Deploy

### Code / Branch Readiness

- [ ] branch is up to date with latest `main`
- [ ] intended Sprint / release changes are merged
- [ ] no unintended debug code, temporary logs, or placeholder values remain
- [ ] changelog / release notes are updated if needed

### CI / Build Validation

- [ ] client typecheck passed
- [ ] client lint passed
- [ ] client tests passed
- [ ] client production build passed
- [ ] server Prisma generation passed in CI
- [ ] server typecheck passed
- [ ] server production build passed
- [ ] built-artifact startup validation passed
- [ ] `/health` validation passed in CI
- [ ] Postgres-backed API smoke validation passed

### Environment / Config Readiness

- [ ] frontend environment variables are correct for deploy target
- [ ] backend environment variables are correct for deploy target
- [ ] `DATABASE_URL` is set correctly
- [ ] `JWT_SECRET` is set correctly
- [ ] `JWT_EXPIRES_IN` is set correctly
- [ ] `CORS_ALLOWED_ORIGINS` is set correctly
- [ ] no stale or test-only config is pointed at production

### Release Materials

- [ ] PR description reflects final shipped scope
- [ ] merge message is prepared
- [ ] changelog entry is ready
- [ ] GitHub release notes are ready

---

## Deploy

### Backend

- [ ] deploy backend service
- [ ] monitor deploy logs for startup failures
- [ ] confirm backend reaches healthy startup state
- [ ] confirm `/health` becomes healthy

### Frontend

- [ ] deploy frontend
- [ ] confirm frontend build completes successfully
- [ ] confirm deployed site loads

---

## Post-Deploy

### Smoke Checks

- [ ] deployed frontend loads successfully
- [ ] hosted `/health` returns success
- [ ] login works
- [ ] logout works
- [ ] authenticated requests succeed
- [ ] no obvious console errors during core flow
- [ ] no obvious network failures during core flow

### Functional Confidence

- [ ] frontend is talking to the intended deployed backend
- [ ] auth flow behaves normally in production
- [ ] core protected routes still work
- [ ] no obvious environment mismatch appears after deploy

### Release Wrap-Up

- [ ] record verification results
- [ ] update Sprint verification notes if needed
- [ ] publish release notes if this is a formal release

---

## Rollback / Recovery

Use this if deployment or smoke validation fails.

- [ ] identify whether failure is frontend, backend, env, or data related
- [ ] redeploy last known good version if needed
- [ ] revert the breaking merge/commit if needed
- [ ] re-run `/health` verification
- [ ] re-run smoke checks after rollback
- [ ] document failure cause before retrying deploy
