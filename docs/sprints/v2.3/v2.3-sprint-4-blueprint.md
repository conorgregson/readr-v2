# Sprint 4 Blueprint — Security & Hardening

Readr v2.3

Objective:
Harden authentication, API boundaries, and request handling so the system fails safely, validates strictly, and behaves consistently in production.

---

# Sprint 4 Goal

- Auth system resilient to malformed and expired tokens
- API boundaries hardened and standardized
- Environment and CORS behavior locked down
- Error handling consistent and production-safe

---

# Scope

## Config & Environment Hardening

- Add centralized env/config module
- Validate required env vars at startup
- Fail fast if critical config is missing or invalid

Validate:

- `DATABASE_URL`
- `JWT_SECRET`
- `JWT_EXPIRES_IN`
- `PORT`
- `NODE_ENV`
- allowed frontend origins

---

## Express Boundary Hardening

- Disable `x-powered-by`
- Add explicit JSON body size limit
- Standardize unknown-route handling
- Safely handle malformed JSON bodies

Ensure:

- unknown routes return JSON `404`
- invalid JSON returns safe `400`
- oversized request bodies are rejected safely

---

## Auth Security

- Refactor auth middleware into centralized error flow
- Normalize JWT verification behavior
- Reject malformed auth headers safely
- Validate token payload shape strictly
- Use env-driven token expiry instead of hardcoded value

Cover:

- missing token
- malformed bearer header
- malformed token
- expired token
- invalid signature
- invalid payload

---

## CORS Hardening

- Replace open `cors()` usage with env-based allowlist
- Prevent wildcard behavior in production
- Preserve local dev usability
- Allow non-browser tools like Postman/curl where appropriate

---

## Error Handling Standardization

- Keep one consistent API error shape
- Route auth failures through shared error handler
- Limit public error detail exposure
- Log unexpected failures server-side only

Rules:

- expose validation details only for safe validation failures
- do not leak stack traces
- do not leak internal server / Prisma / JWT details

---

## Validation Tightening

- Add `.strict()` to request object schemas
- Reject unknown fields across auth, books, sessions, and backup import
- Fix validation normalization edge cases
- Preserve existing merged-state validation in services

Includes:

- auth schema strictness
- books schema strictness
- sessions schema strictness
- backup import schema strictness
- session notes empty-string normalization cleanup
- duplicate imported session id rejection
- optional import size caps if needed

---

## Logging Baseline

- Improve consistency of server-side logs
- Track auth failures safely
- Track unexpected server errors
- Avoid logging secrets or raw tokens

---

## Rate Limiting (Optional)

- Add basic protection to:
  - `POST /api/auth/login`
  - `POST /api/auth/register`

Only include if core hardening work is complete first.

---

# Acceptance Criteria

- Missing, malformed, expired, and invalid JWTs all return a safe standardized `401`
- Auth middleware uses the shared error pipeline instead of ad hoc response logic
- Required env vars are validated at startup and fail fast if missing
- Production CORS only allows configured origins
- JSON request bodies have an explicit size limit
- Unknown routes return standardized JSON `404`
- Malformed JSON requests return safe `400`
- Request schemas reject unknown fields on auth, books, sessions, and backup import endpoints
- Validation details are only exposed for safe validation failures
- No internal errors, stack traces, or sensitive details leak to clients

---

- duplicate session ids rejected
