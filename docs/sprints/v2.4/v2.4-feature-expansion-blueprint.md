# Readr v2.4 — Feature Expansion Blueprint

Post-API Growth Phase

---

# Purpose

v2.4 reintroduces and expands advanced UX features that existed in v1.9
and were intentionally deferred during the v2.1 frontend rebuild
and v2.2 API migration.

This phase focuses on:

- Power-user workflows
- Motivation systems
- Multi-object mutation
- Insight and analytics

All expansion occurs on top of a stable API-backed architecture.

---

# Version Context

- v2.0 — Backend & CI foundation
- v2.1 — React frontend rebuild (parity lock)
- v2.2 — API integration & persistence migration
- v2.3 — Identity & data ownership
- v2.4 — Feature expansion (this phase)

No architectural migration occurs in v2.4.
Only controlled feature layering.

---

# Core Expansion Areas

---

## 1️) Bulk Edit System

### Objective

Enable multi-book mutation workflows without breaking undo or integrity rules.

### Scope

- Multi-select UI for books
- Batch status updates
- Batch delete (with grouped Undo)
- Batch metadata updates (format, flags)

### Guardrails

- Undo must support multi-object rollback
- All operations atomic at API layer
- No partial mutation states
- No bypass of store → service boundary

---

## 2️) Motivation & Progress Systems

### Badges

- Total books milestones
- Pages milestones
- Reading streaks
- Session consistency

### Streak Engine

- Consecutive day tracking
- Reset rules
- Grace window (optional)

### Architecture

- Computed on server in v2.4+
- Not derived purely in UI
- Exposed via read-only API endpoint

---

## 3️) Insights & Analytics

### Visualizations

- Reading over time
- Pages per month
- Session duration trends
- Format breakdown

### Constraints

- Charts are view-only
- No direct mutation
- Computed summaries exposed via API

---

## 4️) Saved Filters & Advanced Views

- Save filter presets
- Quick toggle between saved views
- Pin favorite filters

Server-backed persistence.

# Risk Controls

- Feature flags optional
- No schema rewrites
- No breaking API changes
- Undo must extend, not regress

---

# Exit Criteria for v2.4

- Bulk edit supports grouped Undo
- Badges correctly derive from API
- No regression in CRUD
- No architectural boundary violations
- Performance acceptable with 2,000+ books

---

# Out of Scope

- Social features
- Public sharing
- Multi-user accounts (future phase)
