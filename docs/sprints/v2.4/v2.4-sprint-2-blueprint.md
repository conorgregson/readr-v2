# Sprint 2 Blueprint — Saved Views & Advanced Library Controls

Readr v2.4

Objective:
Improve usability for larger libraries with persistent, user-scoped library views.

---

# Sprint 2 Goal

- Users can save and reuse library views
- Filters persist server-side
- View switching is fast and reliable
- Large-library browsing becomes more efficient

---

# Scope

## Saved Views

- Save filter presets
- Save sort state
- Name saved views
- Quick-toggle between saved views
- Pin and default saved views
- Rename saved views
- Delete saved views

---

## Persistence

- Server-backed user-scoped persistence
- Stable serialization of view definitions
- Safe restore after login/session recovery

---

## UX

- View switcher UI
- Inline save flow for new views
- Default/pinned affordances
- Active-view management actions:
  - rename
  - pin/unpin
  - set/unset default
  - delete
- Empty-state handling for missing/deleted views
- No regression in search/filter interactions

---

## Non-Goals / Deferred

- In-place overwrite of a previously applied saved view after drifting into Current view
- “Update View” content overwrite flow
- Recovering a prior applied view as an overwrite target after Current view drift

These overwrite behaviors are deferred to a future sprint so Current view semantics remain clear and honest in Sprint 2.

---

# Acceptance Criteria

- Users can save and reapply named library views
- Saved views persist across refresh and login restore
- Filters + sort restore correctly
- Users can rename, pin, default, and delete saved views
- Search/filter/view interactions remain stable
- Current view semantics remain accurate after manual filter/search/sort changes
- Library UX remains performant with large datasets
